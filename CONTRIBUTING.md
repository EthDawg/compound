# Contributing to Compound

You don’t need to write code to contribute. Useful contributions include a
sourced correction, an overlooked company connection, a clearer explanation or
a reproducible interaction bug.

## Start with the smallest useful change

- **Research correction:** link the affected page, the original source and what
  needs to change. Prefer company announcements, product documentation and
  firsthand professional accounts. Include the relevant date and region.
- **Bug:** describe what you did, what happened and what you expected. Include
  the page URL and browser; a screenshot helps for layout issues.
- **New study or substantial redesign:** open an issue with the proposed
  contribution before building it, so we can agree on scope.

[Open an issue](https://github.com/EthDawg/compound/issues/new) or submit a focused
pull request. Ethan maintains the shared edition and reviews contributions for
fit, evidence and usability.

## Keep the project’s character

- Explain the few choices that make a company distinctive. Connect its history
  and strategy to the product experience.
- Preserve Compound’s shared navigation and each company’s identity. Don’t
  relabel another company’s interface or essays.
- Keep facts, vendor claims and interpretations distinguishable. Attach sources
  to claims; don’t turn unknowns into estimates.
- Separate local delivery from global capability, appointments from acquisitions,
  and current features from plans.
- Use fictional records in App scenarios. Research real companies and people
  through relevant public sources.

For code changes, follow [the development guide](docs/development.md). Describe
the resulting behaviour and how you checked it in your pull request. Browser
testing, when performed, should be reported separately from build and unit-test
results.
